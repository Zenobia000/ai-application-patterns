# Composite Pipelines：複合式應用的拆解法

> 現在真正讓人驚豔的 AI 案例，幾乎都不是單一工具，而是好幾種能力串起來的：
>
> **一張概念圖 → 轉 3D → 在 Blender 清理與綁骨 → 放進遊戲 → 再用 Blender 擺鏡頭 → 讓影片模型渲染成廣告 → 自動剪輯、上字幕、輸出三種比例。**
>
> 這份文件回答：**看到這種複合案例時，怎麼拆？要自己做一條時，怎麼接？**

---

## 1. 三個概念：原子能力、交接物、黏著層

```text
[原子能力] ──(交接物)──▶ [原子能力] ──(交接物)──▶ [原子能力]
      └───────────── 黏著層（Agent / Workflow / Code）─────────────┘
```

| 概念 | 意思 | 例子 |
|---|---|---|
| **原子能力（Capability Atom）** | 一次「輸入模態 → 輸出模態」的轉換，通常由一個模型或一個工具完成 | 圖 → 3D、3D → 渲染圖、長影片 → 逐字稿 |
| **交接物（Handoff Artifact）** | 兩個步驟之間傳遞的檔案。**它就是兩個工具之間的合約** | PNG、GLB、FBX、MP4、SRT、剪輯決策 JSON |
| **黏著層（Glue）** | 誰負責把步驟接起來、出錯時誰處理 | Claude 透過多個 MCP、ComfyUI 節點圖、n8n、Python 腳本 |

**關鍵洞察**：複合應用最常壞的地方不在原子能力（模型都很強），而在 **交接處**：比例不對、座標軸不同、貼圖掉了、影格率不一致、字幕時間錯位。

## 2. 原子能力目錄

依「輸入 → 輸出」整理。每個原子能力都對應到 P1–P6 的某個 Pattern。

### 2.1 影像與 3D

| 代號 | 原子能力 | 主要 Pattern | 代表工具 | 交接物 | 自動驗證難度 |
|---|---|---|---|---|---|
| **V1** | 文字 → 圖像（概念圖、角色設定） | P1 | gpt-image、Nano Banana、Midjourney、Higgsfield Soul | PNG | 難 |
| **V2** | 圖像 → 圖像（改圖、多視角、去背、換背景） | P1 | 影像編輯模型、ComfyUI | PNG（含透明） | 難 |
| **V3** | 圖像 → 3D 模型 | P1 | Hunyuan3D、TRELLIS、Tripo、Meshy、Rodin | GLB / OBJ | 中（可量面數、檢查破面） |
| **V4** | 3D → 3D（減面、UV、貼圖、修正、比例） | P3 + P4 | Blender（bpy / blender-mcp） | GLB / FBX / .blend | 中 |
| **V5** | 3D → 綁骨 / 動畫 | P1 + P4 | Mixamo、Tripo / Meshy 自動綁骨、UniRig | FBX / GLB（含骨架） | 中 |
| **V6** | 3D → 場景與鏡頭（擺放、打光、運鏡） | P4 + P6 | Blender MCP、Spline | .blend | 中（截圖檢查） |
| **V7** | 場景 → 渲染（彩圖、深度圖、法線圖、線稿） | P4 | Blender（Cycles / EEVEE） | PNG 序列 / MP4 | 易 |
| **V8** | 3D → 引擎 / 網頁 / AR / 列印 | P3 | Three.js、Godot、Unity、USDZ、STL | GLB / USDZ / STL | 易（能不能載入） |

### 2.2 影片與聲音

| 代號 | 原子能力 | 主要 Pattern | 代表工具 | 交接物 | 自動驗證難度 |
|---|---|---|---|---|---|
| **M1** | 圖像 → 影片（首尾影格、運鏡） | P1 | Kling、Veo、Seedance、Higgsfield | MP4 | 難 |
| **M2** | 影片 → 影片（風格轉換、以渲染/深度控制生成） | P1 | Runway、ComfyUI（ControlNet / V2V） | MP4 | 難 |
| **M3** | 文字 → 語音 / 音樂 / 音效 | P1 | TTS、配音與聲音複製、音樂模型 | WAV / MP3 | 中 |
| **M4** | 影音 → 逐字稿（含時間碼） | P2 | Whisper、FunASR | SRT / JSON | 易 |
| **M5** | 逐字稿 → 剪輯決策（選精華、排順序） | P2 | LLM | 剪輯決策 JSON / EDL | 中 |
| **M6** | 剪輯決策 → 成片（剪接、字幕、轉直式、配樂） | P3 + P4 | FFmpeg、Remotion、MoviePy、剪映草稿、DaVinci Resolve API | MP4 | 易（格式）/ 難（節奏） |
| **M7** | 字幕翻譯 / 配音翻譯 | P2 + P1 | LLM + TTS | SRT / MP4 | 中 |

### 2.3 程式與流程

| 代號 | 原子能力 | 主要 Pattern | 代表工具 | 交接物 |
|---|---|---|---|---|
| **C1** | 需求 → 可執行程式（遊戲、網頁、檢視器） | P3 | Claude Code、Codex | Repo / 網址 |
| **C2** | 瀏覽器試玩 / 截圖驗收 | P6 | Playwright MCP | 截圖 / 測試報告 |
| **C3** | 批次與排程 | P5 | n8n、ComfyUI API | 執行紀錄 |

## 3. 交接物就是合約

每一個交接處都要事先講好規格。以下是最常見的「交接事故」：

| 交接處 | 常見事故 | 合約應寫明 |
|---|---|---|
| V3 → V4（生成模型 → Blender） | 模型大小隨機、面數幾十萬、原點不在腳底 | 單位（公尺）、高度、面數上限、原點位置 |
| V4 → V8（Blender → 網頁/引擎） | Blender 是 Z 軸朝上，glTF 是 Y 軸朝上；程序化材質匯出後消失 | 格式 GLB、Y-up、貼圖烘焙成圖片、檔案大小上限 |
| V5 → V8（綁骨 → 遊戲） | 動畫名稱對不上、骨架命名不同 | 動畫片段名稱（idle / walk / jump）、骨架標準 |
| V7 → M2（渲染 → 影片模型） | 解析度、比例、影格數不符模型限制 | 解析度、秒數、fps、控制圖類型（深度/線稿） |
| M4 → M5（逐字稿 → LLM） | 時間碼遺失，剪不回去 | JSON 必須保留每段的開始/結束秒數 |
| M5 → M6（剪輯決策 → 成片） | LLM 給的秒數超出影片長度 | 決策 JSON schema + 驗證秒數範圍 |
| 任何生成 → 下一步 | 角色 / 商品不一致 | 參考圖、角色 ID、固定風格描述 |

**實務建議**：在專案根目錄放一份 `PIPELINE.md`，列出每個交接物的規格。這份文件同時給人看、也給 Agent 看。

## 4. 黏著層：誰把步驟接起來？

| 黏著方式 | 適合 | 優點 | 缺點 |
|---|---|---|---|
| **人工手動** | 探索期、做一次 | 最有彈性 | 無法重現、無法批次 |
| **Agent + 多個 MCP**（如 Claude + Higgsfield MCP + Blender MCP） | 每次內容都不同的創作 | 用自然語言串接、會自己處理小錯誤 | 每次結果不同、成本難預估 |
| **節點工作流**（ComfyUI） | 生成步驟固定、參數要微調 | 可視化、可重現、可存成範本 | 跨軟體能力有限 |
| **Workflow 引擎**（n8n） | 批次、排程、跨 SaaS | 可重跑、可監控 | 不適合重度媒體處理 |
| **程式碼**（Python / FFmpeg / Remotion） | 確定性步驟（剪接、轉檔、合成） | 最穩定、最便宜 | 需要寫程式（可讓 Agent 寫） |

**經驗法則**：

- **創意與判斷** 交給 Agent
- **生成** 交給模型（透過 MCP / API）
- **確定性步驟**（轉檔、剪接、縮放、合成）交給程式碼
- **重複執行** 交給 Workflow

## 5. 複合程度的五個等級

| 等級 | 描述 | 例子 |
|---|---|---|
| **L0 單點** | 一個工具完成一件事 | 用 Midjourney 生一張圖 |
| **L1 手動串接** | 人在多個工具之間下載、上傳 | 生圖 → 下載 → 上傳到 Tripo → 下載 GLB → 開 Blender |
| **L2 Agent 串接** | Agent 透過多個 MCP 在同一個對話中完成 | Claude 用 Hyper3D 生成模型、在 Blender 擺好、渲染截圖 |
| **L3 可重現流程** | 流程被固定成腳本或工作流，換輸入就能重跑 | ComfyUI 工作流、Remotion 模板、n8n |
| **L4 有驗證的自動迴圈** | 每個交接點都有檢查，失敗會自動重試或回報 | Agent 生成 → 截圖 → 檢查面數與比例 → 修正 → 通過才進下一步 |

**工作坊的目標是讓學員從 L1 走到 L2，並理解 L3、L4 需要什麼。** 做過一次 L1 的人，才知道 L2 的 Agent 替你省掉了什麼、又在哪裡會出錯。

## 6. 拆解方法：五個步驟

以「幫社團吉祥物做一支 15 秒的 3D 動畫廣告」為例：

### 步驟 1：寫下最終交付物

> 一支 15 秒、9:16、有字幕與配音的影片；主角是社團吉祥物，外型在每一鏡都一致。

### 步驟 2：往回推需要哪些交接物

```text
成片 MP4
 ← 剪好的鏡頭 + 字幕 SRT + 配音 WAV
 ← 每一鏡的影片片段
 ← 每一鏡的渲染圖（決定構圖與鏡頭）+ 角色參考圖
 ← 擺好姿勢與鏡頭的 3D 場景
 ← 綁好骨的吉祥物 3D 模型
 ← 吉祥物 3D 模型
 ← 吉祥物概念圖（多視角）
```

### 步驟 3：每一條邊對應一個原子能力與工具

| 邊 | 原子能力 | 工具選擇 |
|---|---|---|
| 設定 → 概念圖 | V1 + V2 | 生圖模型（多視角） |
| 概念圖 → 3D | V3 | Hunyuan3D / Tripo（或 blender-mcp 內建的 Hyper3D / Hunyuan3D） |
| 3D → 綁骨 | V5 | Mixamo / 自動綁骨 |
| 綁骨 → 場景與鏡頭 | V6 | Blender MCP |
| 場景 → 渲染 | V7 | Blender |
| 渲染 → 影片 | M1 / M2 | Higgsfield / Kling（以渲染圖為首影格或控制） |
| 腳本 → 配音 | M3 | TTS |
| 片段 → 成片 | M6 | Remotion / FFmpeg / 剪映 |

### 步驟 4：標出驗證點

| 交接點 | 誰檢查 | 檢查什麼 |
|---|---|---|
| 概念圖 | 人 | 像不像我們的吉祥物？ |
| 3D 模型 | 程式 + 人 | 面數、尺寸、有無破面；轉一圈看 |
| 鏡頭 | Agent 截圖 + 人 | 構圖、角色有沒有出鏡 |
| 影片片段 | 人 | 角色一致性（最高風險點） |
| 成片 | 程式 + 人 | 秒數、比例、字幕錯字；節奏 |

### 步驟 5：選黏著層

- 探索期：Claude + Blender MCP + Higgsfield MCP（L2）
- 定案後：把剪輯寫成 Remotion 模板、把生成參數存成 ComfyUI 工作流（L3）

## 7. 為什麼要先拆再整合

| 如果直接做整合 | 如果先拆成原子能力 |
|---|---|
| 壞了不知道是哪一步 | 每一步都有獨立的輸入輸出，可以單獨重跑 |
| 換一個工具要全部重來 | 只換一個原子能力，合約不變就能接上 |
| 學生學到的是一套特定工具的按鈕 | 學生學到的是「圖 → 3D」這種能力，工具換了也會用 |
| 無法評估哪一步最花時間 | 可以量測每一步的成功率與驗收成本 |

這就是為什麼 Repo 的 Lab 設計成 **先練單一原子能力，再練串接**：

```text
Lab 03 生成影片   Lab 06 Blender MCP   Lab 05 Coding Agent 做遊戲
        \               |                    /
         \              |                   /
     Lab 09 圖→3D→遊戲   Lab 10 AI 剪輯   Lab 11 Blender 預演→AI 影片
                  \          |          /
               Capstone：一家店的 AI 開幕週
```
