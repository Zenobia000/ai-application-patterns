## 2. 每個特性在問什麼

| 特性 | 核心提問 | 若此特性「高」，你需要 |
|---|---|---|
| **非結構資料理解** | 輸入是 PDF、Email、對話、圖片這類沒有欄位的東西嗎？ | LLM 做理解/抽取，而不是寫死規則 |
| **正確性／可驗證** | 錯了會怎樣？有沒有「標準答案」可以比對？ | 引用來源、測試、規則檢查、人工覆核 |
| **視覺品質** | 成果好不好是「看了才知道」嗎？ | 參考圖、風格鎖定、多版本挑選、人眼審查 |
| **結構化輸出** | 成果要被其他程式讀取嗎？（JSON、表格、程式碼、Scene） | Schema、Structured Output、驗證器 |
| **狀態／互動** | 需要記住前面發生的事嗎？使用者會來回操作嗎？ | Session/記憶管理、狀態機、資料庫 |
| **多工具整合** | 要碰幾個外部系統？ | MCP / API 整合、錯誤處理、權限設計 |
| **Deterministic Control** | 同樣輸入需要得到同樣結果嗎？ | 把關鍵步驟交給程式或規則，LLM 只做判斷 |
| **Batch Automation** | 要做一次，還是每天做一百次？ | Workflow、排程、重試、成本控管 |
| **人工驗收成本** | 人要花多少時間確認成果可以用？ | 決定這個應用真正的 ROI |

## 3. 三個最重要的觀察

### 3.1 Prompt Engineering 不可能是所有 AI 應用的統一解法

每個領域的「最大難題」不同：

| 領域 | 最大難題 | Prompt 能解決多少？ |
|---|---|---|
| 3D | 幾何正確、Scene 一致性 | 少。需要工具回饋（截圖、Scene 查詢） |
| 影片 | 時間一致性（角色、場景前後一致）、視覺品質 | 部分。需要參考圖、分鏡、多次生成挑選 |
| 企業流程 | 可靠性、權限、失敗重跑 | 少。需要 Workflow 引擎與規則 |
| 知識問答 | 找對資料、不要亂編 | 部分。需要檢索品質與引用 |
| 軟體 | 邏輯正確、可以跑 | 部分。需要執行、測試、除錯迴圈 |

### 3.2 「人工驗收成本」決定一個應用值不值得做

AI 產出很快，**驗收很慢**的應用，時間只是從「做」移到「檢查」。
好的 AI 應用設計會想辦法 **降低驗收成本**：

- 程式 → 自動測試
- 知識 → 附引用，讓人一鍵對照原文
- 3D / 網頁 → 自動截圖給人看，而不是讓人打開軟體檢查
- 影片 → 一次產多版，人只負責挑

### 3.3 可驗證性越高，越適合交給 Agent 自主迭代

Agent 能「自己修正」的前提，是它有辦法知道自己錯了。

```text
可自動驗證（程式測試、Schema 檢查）    → 適合讓 Agent 自主跑多輪
部分可驗證（截圖給模型看、規則檢查）   → Agent 迭代 + 人工最終確認
難以驗證（美感、品牌調性）             → Agent 產多版，人類決策
```

## 4. 使用方式：分析一個新案例

拿到一個案例（例如「AI 幫咖啡店做 IG 貼文」），逐列填表：

| 問題特性 | 高/中/低 | 理由 |
|---|---|---|
| 非結構資料理解 | 中 | 要理解店家描述與照片 |
| 正確性 | 中 | 價格、營業時間不能錯 |
| 視覺品質 | 高 | IG 是視覺平台 |
| 結構化輸出 | 低 | 最後是圖片和文案 |
| 狀態／互動 | 低 | 一次性產出 |
| 多工具整合 | 中 | 生圖、排版、發文 |
| 可控性 | 中 | 品牌色與字體要固定 |
| 批次化 | 高 | 每週都要發 |
| 人工驗收成本 | 高 | 每張都要老闆看過 |

**結論**：高視覺品質 + 高批次 + 高驗收成本 → 用 **P1 Generate** 產多版，用 **P5 Workflow** 排程，把「價格、營業時間」從資料表帶入而不是讓模型生成（提高可控性），最後保留人工挑選。

這張表就是課堂上最核心的思考工具。
